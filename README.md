# Список задач (To-Do + AI Assistant)

Веб-приложение для планирования личных задач по дням календаря с локальным хранением, drag-and-drop сортировкой, голосовым вводом и встроенным ИИ-помощником. Проект собран на Nuxt 4 + Vue 3 + TypeScript и включает серверный BFF-прокси на Nitro для безопасной работы с ИИ через n8n.

---

## Возможности

- **Планирование по календарю:** выбор любой даты (`v-calendar`), быстрый переход к сегодняшнему дню, индикация дней с задачами и работа с локальной датой (`YYYY-MM-DD`) без смещения часовых поясов.
- **Управление задачами:** создание (до 200 символов), отметка о выполнении, удаление, счетчик прогресса и фильтрация (`Все`, `Активные`, `Выполненные`).
- **Сортировка перетаскиванием (Drag-and-Drop):** кастомный контроллер (`app/utils/taskDragSession.ts`) с поддержкой мыши, тач-экранов и клавиатуры. Сортировка активна в режиме `Все`, при переключении фильтра или нажатии `Escape` активный drag отменяется.
- **Защищенное локальное хранение (`localStorage`):** формат `{ version: 1, tasks }` под ключом `todo-nuxt:tasks:v1`, защита от тихой перезаписи между вкладками (проверка снапшота перед сохранением) и сценарии восстановления/сброса при повреждении данных.
- **ИИ-помощник (`POST /api/ai-chat`):** чат в контексте выбранного дня (до 40 задач дня и до 6 последних сообщений диалога). Поддерживает 3 режима: обычный диалог (`chat`), создание списка задач из свободного текста (`create_tasks`) и декомпозицию выбранной задачи на шаги (`split_task`). На экране приветствия рендерится интерактивная сфера на WebGL-шейдере (`TaskAiOrb`) с поддержкой `prefers-reduced-motion`.
- **Контроль действий ИИ:** ассистент только предлагает изменения в виде карточек (`add_tasks`, `split_task`) и не может удалять или изменять существующие задачи. Новые задачи попадают в список только после ручного нажатия кнопки `Добавить` (одним батчем через `addTasksBatch`).
- **Голосовой ввод (`POST /api/ai-transcribe`):** микрофон встроен в форму новой задачи и в поле ИИ-чата. Запись в браузере через `MediaRecorder` (`webm`, `ogg`, `mp4`, `m4a`, `wav`; до 45 с и до 1 МБ аудио) отправляется на распознавание (n8n + Whisper) и подставляется в поле редактирования без автоотправки.
- **Адаптивность и доступность (a11y):** на десктопе трехколоночная сетка, на планшете и телефоне выдвижные панели (`dialog`) с `inert` для фона, удержанием фокуса (`Tab` / `Shift+Tab`), закрытием по `Escape` и возвратом фокуса на кнопку открытия.

## Стек

- **Frontend:** Nuxt 4 (`4.1.3`), Vue 3 (`3.5`), TypeScript, Pinia, SCSS (`vc()`-масштабирование), `v-calendar`, WebGL (GLSL)
- **Server / BFF:** Nuxt Nitro, `h3` (прокси к n8n webhook, валидация, лимитер)
- **Тесты и качество кода:** встроенный runner Node.js (`tsx --test`, 84 теста), ESLint, Stylelint, `vue-tsc` (`nuxt typecheck`)
- **Деплой:** Docker (multi-stage сборка на `node:22-slim`), Docker Compose

## Архитектура и безопасность

1. **Изоляция секретов в BFF (`server/`):** клиент общается только с эндпоинтами Nuxt (`/api/ai-chat` и `/api/ai-transcribe`). Адрес вебхука n8n и авторизационный заголовок передаются исключительно через `runtimeConfig` на сервере и не попадают в браузер.
2. **Контроль входящего трафика (`server/utils/aiBody.ts`, `server/utils/aiRateLimit.ts`):**
   - потоковое чтение тела запроса с прерыванием при превышении лимита (64 КБ для чата, 1.5 МБ для аудио) и таймаутами;
   - единый ограничитель нагрузки для чата и транскрибации: `1` активный запрос на IP, `4` одновременно глобально (с гарантированным освобождением слота в `finally`), `12` запросов в минуту на IP и `200` запросов в сутки (UTC);
   - опциональное чтение `X-Forwarded-For` (`NUXT_AI_TRUST_PROXY`) для корректной работы за reverse proxy.
3. **Валидация ответов ИИ (`shared/utils/aiChat.ts`):** сервер парсит ответ модели, убирает лишнюю markdown-обертку JSON, отфильтровывает неподдерживаемые действия, нормализует даты и генерирует уникальные ID карточек на стороне приложения.

## Локальный запуск

### Требования

- Node.js `22+`
- `npm`

### Установка и разработка

```bash
npm install
cp .env.example .env
npm run dev
```

Если `.env` не настраивать или оставить пустым, сам планировщик задач (календарь, создание, фильтрация, DnD, `localStorage`) будет работать полностью. Переменные окружения нужны только для ИИ-чата и распознавания речи через n8n.

### Production-сборка (SSR)

```bash
npm run build:server
npm run start:server
```

Для статической генерации без серверных API-маршрутов:

```bash
npm run build
```

## Переменные окружения

Шаблон находится в [`.env.example`](.env.example), дефолтные значения заданы в [`nuxt.config.ts`](nuxt.config.ts).

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `NUXT_N8N_WEBHOOK_URL` | Для ИИ и голоса | `""` | URL webhook-триггера в n8n |
| `NUXT_N8N_AUTH_HEADER_NAME` | Для ИИ и голоса | `X-Todo-Ai-Token` | Имя HTTP-заголовка авторизации для n8n |
| `NUXT_N8N_AUTH_HEADER_VALUE` | Для ИИ и голоса | `""` | Секретный токен заголовка авторизации |
| `NUXT_AI_TRUST_PROXY` | За прокси | `false` | Доверять `X-Forwarded-For` при подсчете лимитов по IP (`true` за Nginx) |
| `NUXT_AI_RATE_LIMIT_PER_MINUTE` | Нет | `12` | Лимит ИИ-запросов в минуту с одного IP |
| `NUXT_AI_DAILY_REQUEST_LIMIT` | Нет | `200` | Общий дневной лимит ИИ-запросов (UTC) |
| `NUXT_AI_MAX_CONCURRENT_PER_IP` | Нет | `1` | Максимум параллельных ИИ-запросов с одного IP |
| `NUXT_AI_MAX_CONCURRENT_GLOBAL` | Нет | `4` | Максимум параллельных ИИ-запросов на сервер |

## Деплой в Docker

В проекте подготовлены [`Dockerfile`](Dockerfile), [`docker-compose.yml`](docker-compose.yml) и [`.dockerignore`](.dockerignore):

- используется multi-stage сборка на `node:22-slim`: в финальный образ попадает только собранный каталог `output/` и запускается под непривилегированным пользователем `node`;
- настроен встроенный `HEALTHCHECK` на `http://127.0.0.1:3000/`;
- сервис подключается к внешней Docker-сети прокси и n8n (`wapdiz_app-net`) без проброса порта наружу (`wapdiz-todo-1:3000`).

Запуск на сервере:

```bash
cp .env.example .env
# заполнить NUXT_N8N_WEBHOOK_URL и NUXT_N8N_AUTH_HEADER_VALUE
docker compose up -d --build
```

Нюансы при настройке reverse proxy (Nginx / Nginx Proxy Manager):

- включить HTTPS (браузеры разрешают `MediaRecorder` / `getUserMedia` только по HTTPS или на `localhost`);
- выставить `client_max_body_size 2m;` (для загрузки голосовых фрагментов до 1.5 МБ);
- перезаписывать `proxy_set_header X-Forwarded-For $remote_addr;` при `NUXT_AI_TRUST_PROXY=true`, чтобы клиент не мог подменить IP-адрес в заголовке.
